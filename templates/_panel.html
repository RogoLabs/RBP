What is a Reserved but Public CVE ID?

A Reserved but Public CVE ID is one a CNA has reserved and that appears in a public advisory, while the CVE Record itself is still unpublished. Anyone pulling the CVE List sees nothing. The advisory is already out there.

That is not our term. It is the CVE Program's own, and its glossary definition is what this site counts:

A CVE ID in the “Reserved” state that is referenced in one or more public sources but for which a CVE Record has not been published.

What the policy expects

RBP Policy v2.0.0, approved by the CVE Board on 13 August 2026, expects a record within 72 hours of disclosure, and sets out a real process: a Root notifies the CNA with a remediation timeline, CNAs must prioritise requests to publish critical RBPs, and repeat failures escalate up to decertification. None of that process is observable from outside, so nobody can tell whether it ran.

Why no CNA is named here

The state itself is observable, and the CVE Services API will confirm it. What it will not tell you is who reserved the ID: "owning_cna": "[REDACTED]". CNA Rule 4.5.1.7 both permits and limits naming, and it binds the Secretariat rather than anyone else:

The Secretariat MAY publicly identify the CNA who reserved the CVE ID 24 hours after a CVE ID has been Publicly Disclosed. Otherwise, the Secretariat SHOULD NOT publicly identify the CNA until the CVE Record has been published.

So this site reconstructs the owner from public data, publishes how often that reconstruction is wrong, and asks for something narrower instead: unblind owning_cna only for reserved IDs already publicly referenced for more than 24 hours. A blanket unblinding would be unsafe, and this project is the reason we know that: the same block-boundary reasoning that recovers an owner would let anyone derive pre-disclosure ownership across the whole reserved space.

The Program used to publish this

The Program used to publish a count of these. A quarterly table ran on the CVE Metrics page and was commented out in February 2022, as item 2 of a three-item quarterly-to-annual table restructuring (cve-website #842), a fortnight after the v1.0 policy PDF was withdrawn to be “replaced with a new version of the document at a later date” (#835). That replacement is now v2.0.0. The series never came back. Its final column already read N/A, so it had stopped being populated before anyone commented it out.

This site will not be that series, and is not comparable to it. That table was a quarterly flow of newly identified RBPs, measured with authoritative internal access, falling from 4,326 in Q1 2017 to 350 in Q3 2021. What is being built here is a live stock, discovered from downstream advisory feeds that reach a minority of CNAs, with the owner inferred rather than known. Both numbers would be real. They would not be the same measurement, and neither replaces the other.

RBP Policy v2.0.0 names “Program metrics and audits” as one of the Program's own channels for identifying RBPs. Our ask is for the public face of that channel. Until then, this site is being built to publish the outside view.

How this is measured

Ten public advisory feeds are read every six hours and everything they reference is checked against the CVE List. Nothing appears here until it has been publicly referenced for at least {{ summary.get('min_age_days', 7) }} days, which is {{ ((summary.get('min_age_days', 7) * 24) / 72) | round(1) }}x the 72-hour expectation, so ordinary latency and short coordinated-disclosure windows are excluded.

The feeds reach a minority of CNAs, so every number here is a floor, never a census. The method in full, and the policy quotations.

If a row should not be listed

Email rbp@rogolabs.net giving the CVE ID and nothing else. No reason, no detail, no confirmation that a vulnerability exists: a request naming only an identifier does not distinguish an embargo from a wrong row, and asking for a reason would make the request itself a disclosure. Read by a person.
