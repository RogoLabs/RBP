Reading these honestly

  • Counts are a floor. Only configured feeds are read, so an RBP in an uninstrumented ecosystem does not appear.
  • Owner is inferred and absent wherever the gate did not pass. It is never an authoritative assignment.
  • Days public is a floor measured from the earliest advisory visible here, not the rule's awareness clock.
  • A {{ rule_must }} reading is a candidate, never an established breach.
  • Full method and current accuracy: Method.

Citing a number so it stays resolvable

Do not cite data/rbp.json. It is the latest build and it changes every six hours, so a figure quoted from it resolves later to a file that no longer says what was quoted. On the day this site sets a launch epoch, the count in it changes entirely.

Cite a dated path instead. Every retained snapshot is published at its own URL, written from that day's snapshot rather than from today's numbers wearing that day's name: 

https://rbptracker.org/data/archive/<YYYY-MM-DD>/rbp.json
https://rbptracker.org/data/archive.json        the index of what exists

Stable, not immutable, and the difference is deliberate. A withhold request removes a row from every published artefact including these, because that is the entire point of having a correction channel. So a dated figure can go down later. This project will not promise permanence it is unwilling to honour at the expense of someone asking to be delisted, and an archive that kept rows a CNA had contested would become the reason the withhold did not work. Retention also prunes: the current snapshot, the previous one, and one per month survive.

The contract

Schema version {{ schema_version }}. Both JSON files are wrapped in an envelope carrying the version, the generation time, the buffer, the epoch, the coverage figures and the caveats, so a tool holding the rows also holds the qualifiers. Before this they were bare arrays and every caveat lived only in this HTML, which a tool has no reason to fetch. The version is bumped on any key rename, removal, or change of meaning; new fields do not bump it, so pinning a major version keeps working.

Absence has one spelling per field, listed below. Three conventions used to be in use and none was documented: empty string, null, and the placeholder "unattributed" sitting in the field that otherwise holds CNA short names. That value was the largest in the column by a factor of three, cnas.json had no such entry, and this page documented the opposite, so anyone coding to the documentation treated every abstention as a named CNA. {{ '`owner`' }} is now a CNA short name or null, never a placeholder, and owner_nameable is the field to branch on.

Licence

MIT, same as the source.

Reporting a row. To have one withheld, open a withhold request giving the CVE ID and nothing else, no reason needed; it is withheld on the next build and leaves every file on this page. Prefer not to post publicly? Report privately or email rbp@rogolabs.net. Withheld rows are counted in aggregate on Method and never named.

On the description column. It is an advisory summary, not a title. Two earlier versions of this page were wrong about it in opposite directions: the first called these “advisory titles, reproduced verbatim”, and the correction then described a raw 180-character slice that cut mid-word. Neither describes the field now.

What it is today: the advisory's own summary text, cut at the first sentence boundary, with all URLs and all vulnerability-tracker annotations (NOTE:, Introduced with:, Fixed by:) removed before publication. Those annotations carried commit links, and a pointer to the code that introduced a flaw is not a description of it. Where nothing usable survives, the package name is shown instead. Every remaining character was already published by the feed it came from, and nothing here is original analysis. For some rows the summary does describe a mechanism, because the upstream advisory did.
