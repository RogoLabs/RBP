Some of these may be IDs delegated to you, not withheld by you. RBP Policy v2.0.0 lets a Root direct a CNA-LR to publish an overdue record and transfer ownership, so a Root, TL-Root or CNA-LR can hold IDs precisely because it is the remedy the policy defines. The reservation endpoint publishes no role, no requester and no delegation record, so this site cannot tell which rows those are and does not guess. If any row here is one of them, that is worth saying and this page is wrong about it.

To have a row removed, ask. Open a withhold request and it is withheld on the next build, which runs every six hours. Give the CVE ID and nothing else. No reason, no detail, no explanation, and above all no confirmation that a vulnerability exists. A request with no reason does not distinguish an embargo from a wrong owner from a CNA that would simply rather not be listed, which is the point: the request is public, so it should carry no information beyond the ID.

Requests are public deliberately. It means anyone can check that the withheld count on Method matches the requests actually made, so the lever cannot be used to quietly shrink the headline. If you would rather not post publicly, report privately or email rbp@rogolabs.net; both reach a person rather than the pipeline, so they are handled within five business days rather than on the next build.

What actually happens. Every row is recomputed from public data on every build, so nothing here is stored and edited: a requested row is withheld by a list the pipeline reads before it infers anything, which is why the name never reaches the published accuracy ledger either. A withheld row is counted in an aggregate and never named. This site can only infer owning_cna; the authoritative value is held by your Root and the Secretariat, so an ownership dispute is also worth raising through the CVE Program request form.
